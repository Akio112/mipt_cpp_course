# Занятие 1.1. Каркас и первый детект

> [Лекция 1](../lectures/01/lecture.md): типы, control flow, `std::print`, препроцессор, CE/RE/UB.

К концу занятия агент читает журнал событий, считает события по типам
и печатает детекты по строкам с подозрительными признаками. На сценарии
`phishing_macro` с флагом `--quiet` он печатает ровно одну строку:

```
[DETECT] строка 9, признак wscript.exe: ts=1730000003000 type=process_start pid=1101 ppid=1042 image="C:\Windows\System32\wscript.exe" cmdline="wscript.exe C:\Users\max\AppData\Local\Temp\a.js" user=DESKTOP\max
```

Заготовка пока печатает только `строк 23, из них комментариев 3`. Ни классов,
ни своих функций на этом занятии нет: весь код лежит в `main`.

## Развитие проекта

Конфигурация, сборка и тесты занятия:

```bash
cmake --preset windows -D NANO_EDR_LESSON=1.1
cmake --build --preset windows
ctest --preset windows
```

На Linux вместо `windows` — `linux`. Что делают эти команды, что нужно
установить и откуда их запускать — в [`project/README.md`](../project/README.md).
Ключ один — номер занятия; всё остальное берётся из него.

1. **Убедиться, что сборка и чтение файла работают, до первой своей
   строки.** Запустите заготовку на журнале:
   `./build/windows/Release/nano-edr scenarios/phishing_macro.log`, на Linux —
   `./build/linux/nano-edr scenarios/phishing_macro.log`. Пока не видно, что
   сборка проходит и файл читается, любая ошибка дальше выглядит как ошибка
   в собственном коде. `ctest` на этом шаге даёт три падения из трёх: тесты
   описывают то, что ещё не написано.
2. **Отсечь всё, что не является событием.** Заготовка уже читает журнал
   построчно, но пропускает только строки с `#` первым символом, а
   не-событий больше — [полное определение](#что-не-является-событием).
   Выданные тесты разницы не заметят: в журналах есть только комментарии
   с `#` в начале строки. Проверьте на своём маленьком файле.
3. **Сводка по типам событий.** Посчитайте события каждого типа (поле `type=`)
   и напечатайте, сколько событий всего и сколько каждого типа в отдельности.
   Формат сводки свободный.
4. **Детект на каждый найденный признак.** В каждом событии ищите
   [четыре признака](#список-признаков) и на каждый найденный печатайте
   строку в [формате детекта](#формат-детекта).
5. **`--quiet` — режим сравнения с эталоном.** С этим флагом в `stdout`
   попадают только детекты, сводки там нет. Остальные аргументы
   и [коды завершения](../lectures/glossary.md#exit-code) (exit code) —
   по [таблице](#командная-строка).

## Справочник

### Список признаков

Четыре подстроки, ровно в этом порядке:

```
wscript.exe
.locked
certutil.exe
\Startup\
```

Порядок важен: если в одной строке нашлось несколько признаков, детекты
печатаются в порядке этого списка — по одной строке на признак.

Регистр учитывается. В `phishing_macro` строка 8 содержит путь
`...\Word\STARTUP\...`, и это не признак: поиск без учёта регистра даст
лишний детект, и тест упадёт.

### Формат детекта

```
[DETECT] строка <номер>, признак <признак>: <строка журнала целиком>
```

- `<номер>` — номер строки в файле, начиная с единицы, считая **все** строки:
  и комментарии, и пустые ([почему](#почему-номер-строки-считается-по-файлу)).
- `<признак>` — та подстрока из списка, которая нашлась.
- `<строка журнала целиком>` — ровно то, что прочитано, без изменений
  и без обрезания.

### Что не является событием

- Строка, которая после необязательных пробелов и табуляций начинается
  с `#` или `;`.
- Пустая строка, в том числе из одних пробелов и табуляций.

Всё остальное — событие: текстовая строка вида
`ts=число type=... pid=... key=value`.

### Командная строка

```
nano-edr <журнал> [--quiet]
```

| Код завершения | Когда |
|---|---|
| 0 | журнал дочитан до конца, детекты были или нет |
| 2 | работать не с чем: не указан журнал, лишний аргумент, неизвестный флаг, журнал не открылся |

Сообщение об ошибке печатается в `stderr`. Заготовка уже возвращает 2, когда
журнал не указан или не открылся.

### Что понадобится из библиотеки

Лекция 1 этого не проходила, а занятию оно нужно с первой минуты.

| | |
|---|---|
| `std::ifstream log(path);` | открыть файл на чтение (`<fstream>`); `if (!log)` — не открылся |
| `std::getline(log, line)` | прочитать очередную строку в `std::string`; в условии `while` — пока строки есть |
| `line.find(sub)` | позиция подстроки либо `std::string::npos`, если её нет |
| `line.substr(from, count)` | кусок строки |
| `line.size()`, `line[i]` | длина и символ по индексу |
| `std::vector<std::string>` | список строк (`<vector>`): `push_back`, `size()`, `[i]` |
| `std::print(stderr, "…{}\n", x)` | печать в поток ошибок; `stderr` — из `<cstdio>` |
| `"\\Startup\\"` | обратный слеш в строковом литерале пишется дважды: `\\` — это один символ `\` |

## Тесты

Три случая, по одному на сценарий: `scenarios/phishing_macro.log`,
`scenarios/ransomware.log`, `scenarios/clean_office.log`. Эталоны лежат
в `tasks/1.1/tests/expected/`, скрипт сравнения — `tasks/1.1/tests/run_case.cmake`;
подключаются они ключом `-D NANO_EDR_LESSON=1.1`, правки в вашем
`CMakeLists.txt` не требуют.

Каждый случай запускает

```bash
nano-edr <журнал> --quiet
```

и проверяет две вещи: код завершения 0 и `stdout`, который совпадает
с эталоном побайтово, включая пробелы. Одно исключение — перевод строки:
на Windows `stdout` в текстовом режиме отдаёт `CRLF`, и скрипт сравнения
это учитывает. `stderr` и вывод без `--quiet` не проверяются. При расхождении
тест печатает первую разошедшуюся строку — с неё и начинайте.

**Комментарии в журналах содержат ровно те слова, которые ищет агент.**
В `clean_office.log` есть строка про правило «любой `wscript.exe` — атака»,
в `ransomware.log` — комментарий с `.locked`. Если фильтр из шага 2 сломан,
тесты покажут лишние детекты.

## Почему так устроено

Читать не обязательно, чтобы сдать занятие, но на проверочной об этом
спрашивают.

### Почему номер строки считается по файлу

Номер, посчитанный по событиям, бесполезен: по нему нельзя открыть файл
и посмотреть, что там. Поэтому счётчик увеличивается до всех проверок,
и комментарии с пустыми строками тоже получают номер.

### Почему в эталоне `clean_office` есть детект

Это не ошибка эталона. Сценарий действительно запускает `wscript.exe` —
корпоративный скрипт подключения дисков. Признак-подстрока отличить его
от фишинга не может: разница не в тексте записи, а в том, кто этот процесс
породил и откуда взялся скрипт.
